# Phase 5N BARS Low-Level Policy Training Design

Phase 5N is the main route after the Phase 5M backbone audit. The goal is to
train a low-level policy that is native to BARS graph targets, not borrowed from
GAS or another SOTA method.

## Premise

Graph-based offline RL methods do not have a detachable low-level policy. GAS's
actor is trained with its own TDR representation, keygraph target distribution,
skill normalization, subgoal threshold, and final-goal switching logic. A BARS
policy must likewise be trained with the BARS graph and execution protocol it
will use at test time.

Cross-policy reuse remains useful only as diagnosis:

- it can test whether BARS targets are plausible under a strong policy;
- it cannot support a final BARS algorithm claim;
- it is invalid without target-space and distribution compatibility checks.

## Algorithm Direction

Train a BARS-native planner-conditioned goal policy:

```text
offline trajectories
  -> support-certified option graph
  -> BARS planner/subgoal selector
  -> planner-issued goal distribution
  -> goal-conditioned low-level policy training
  -> natural-start hierarchical evaluation
```

The policy training distribution must include the targets that the planner will
actually emit, not only arbitrary future states.

## Training Data Mixture

Use a controlled mixture of four sample families:

| family | obs | goal | action | purpose |
| --- | --- | --- | --- | --- |
| final-goal hindsight | `s_t` | future/final trajectory state | `a_t` | preserve ordinary GCBC competence |
| support-edge local | `s_u` | edge termination `s_T` | `a_u` | execute certified option edges |
| planner-subgoal replay | `s_u` or natural-start-like state | BARS selected subgoal | `a_u` where support exists | align policy with runtime target distribution |
| recovery/negative-progress | drift states from rollouts | safer local support target | behavior or corrective action when available | reduce repeated failed edge attempts |

The key new component is planner-subgoal replay. It should be generated by
running the current BARS planner/subgoal selector offline over sampled
start-goal queries, recording the exact subgoals it would issue, then extracting
supervised actions only where the offline trajectory supports reaching that
target.

## Loss

Start with behavior cloning, but stratify and report metrics by target source:

```text
L = w_final * MSE(pi(s, g_final), a)
  + w_edge * MSE(pi(s, g_edge), a)
  + w_plan * MSE(pi(s, g_planner), a)
  + w_low_support * balanced_edge_weight * MSE(...)
```

Do not optimize only global validation MSE. Required validation groups:

- final-goal samples;
- support-edge samples;
- planner-issued subgoal samples;
- low-support/high-bottleneck edges;
- long-horizon edges;
- rollout-failed edge attempts when available.

## Representation

Two viable variants should be compared:

1. **Raw goal GCBC**
   - input: raw observation and raw subgoal observation;
   - easiest to integrate with current Phase 3 code;
   - may struggle when raw high-dimensional goals contain irrelevant state.

2. **BARS learned skill / phi policy**
   - learn a BARS representation for graph nodes and policy goals;
   - train policy on normalized skill or `(obs, phi_goal)` inputs;
   - closer to GAS's mature design, but must be trained as part of BARS, not
     borrowed without compatibility.

The immediate implementation should start with raw goal GCBC plus planner
subgoal replay because it reuses current code. If natural-start success remains
0 after enough training, move to a learned BARS skill representation.

## Evaluation Gate

Every candidate policy must be evaluated in this order:

1. offline supervised metrics by target family;
2. direct final-goal natural-start success;
3. BARS hierarchical natural-start success;
4. paired comparison to official GAS under matched env/task/seed protocol.

Success rate is the primary metric. Final L2, completed edges, subgoal reach
rate, and replans are diagnostics.

## Immediate Next Implementation

Build `phase5n/planner_subgoal_dataset.py`:

- load Phase 2/4 graph edges and segments;
- sample start-goal queries from offline episodes;
- run BARS planner/subgoal selector without environment rollout;
- emit `(obs_index, goal_index, action_index, target_source, edge_id)` examples
  only when the selected planner target is supported by a real trajectory
  segment;
- train with `scripts/train_phase5n_planner_subgoal_gcbc.py`;
- evaluate with existing `scripts/run_phase3f_natural_rollout.py`.

This is the first route that can turn BARS graph improvements into a complete
policy-and-planner algorithm.

## Implemented V0

The first implementation is now available:

- `phase5n/planner_subgoal_dataset.py`
- `phase5n/train_planner_gcbc.py`
- `scripts/train_phase5n_planner_subgoal_gcbc.py`
- `configs/phase5n_planner_subgoal_gcbc_antmaze_corebot_H10_B120.yaml`
- `docs/phase5n_planner_subgoal_gcbc_summary.md`

V0 implements a support-safe planner-aware target mixture:

```text
final-goal hindsight
  + support-edge local
  + planner-first-edge replay
```

Planner replay currently uses graph-level shortest-path queries to identify
edges that BARS would issue frequently as immediate subgoals. The supervised
examples are still extracted only from real Phase 2 edge segments. This makes
the training distribution more policy/planner aligned without creating
unsupported targets.

The remaining gap is exact online planner-subgoal replay from natural-start
traces and recovery samples after drift. Those should be added after the full
Phase5N checkpoint is trained and evaluated.
