# Phase 5N Planner-Aware Low-Level GCBC Summary

Phase 5N moves BARS from graph-only improvement toward a complete
graph-policy algorithm. The change is to train the low-level policy on targets
that the BARS planner itself is likely to emit, while keeping every
planner-replay target support-certified by an observed segment.

## Related Work and Code Checked

- GCSL: https://arxiv.org/abs/1912.06088
- RvS supervised offline RL: https://arxiv.org/abs/2112.10751
- GAS official implementation: https://github.com/qortmdgh4141/GAS
- Local GAS code path: `external_src/GAS/O_utils/evaluation.py`
- Prior BARS evidence: `docs/phase4m_planner_relevant_weighting_summary.md`
  and `docs/phase5m_policy_backbone_audit.md`

The resulting design follows the supervised goal-conditioned policy family,
but avoids treating GAS's actor as a detachable component. GAS actor targets
are coupled to GAS TDR phi, keygraph planning, skill normalization, and its own
training distribution. BARS must train a policy on BARS graph targets.

- `tests/test_phase5n_synthetic.py`

The training dataset mixes three support-safe target families:

| target source | observation | goal | action |
| --- | --- | --- | --- |
| final-goal hindsight | offline `s_t` | future state in same episode | offline `a_t` |
| support-edge local | edge segment `s_u` | segment termination `s_T` | offline `a_u` |
| planner-first-edge replay | segment from a planner-used edge | segment termination `s_T` | offline `a_u` |

Planner replay is generated by sampling support-graph start/goal cluster
queries, running support-only shortest-path planning, counting first-edge and
path-edge usage, and lifting those edges in sampling/loss weights. It does not
create kNN/proximity/unsupported targets.

## Analysis

This is the first implemented BARS-native policy-training path that explicitly
matches the planner target distribution. It is more aligned with the final
algorithm than the previous graph-only and borrowed-policy diagnostics.

What is useful:

- BARS can now train on final goals and support-option subgoals in one policy.
- Planner-issued edges are represented as a first-class validation group.
- The implementation keeps unsupported shortcuts out of both graph planning and
  supervised target construction.
- The output model is compatible with the existing natural-start hierarchical
  evaluator.

What remains unproven:

- This does not prove closed-loop success.
- The smoke run does not prove the planner-aware policy is better than the
  100000-step Phase 3A GCBC.
- It does not solve recovery from off-support drift.
- It has not yet been compared to GAS under a matched online protocol.

## Next Gate

Run the full 100000-step config, then evaluate:

1. direct final-goal natural-start success;
2. BARS hierarchical natural-start success using this checkpoint;
3. matched comparison against the current Phase 3A GCBC and official GAS
   protocol records.

If success remains `0.0`, the next policy-side improvement should be a learned
BARS skill/phi representation or rollout-derived recovery training, not another
graph-only planner tweak.
